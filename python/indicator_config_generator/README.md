# Indicator Config Generator

**Status**: 🚧 Under Design

## Overview

The Indicator Config Generator is responsible for generating indicator configurations at **compile time** from Python scripts.

This is a **build-time tooling concern** - it generates JSON configurations that are then loaded by the `indicator_engine` at runtime.

## Key Principles

1. **Compile-Time Only**: Indicator definitions are generated at build time, not runtime
2. **Dual Sources**: System-wide indicators (config) + strategy-specific indicators
3. **Python → JSON**: Python scripts generate JSON configs, Rust loads them

## Architecture

```
Python Scripts (Separate Workspace)
    ↓
Generate indicator configs (Python)
    ↓
Export to config/indicators.json
    ↓
Git commit / deploy
    ↓
Rust system loads JSON at startup
    ↓
Indicator Engine registers indicators
```

## Indicator Sources

### 1. System-Wide Indicators

- Generated by Python scripts for overall system use
- Stored in `config/indicators.json`
- Available to all strategies and levels
- Examples: Common SMAs, EMAs for levels, etc.

### 2. Strategy-Specific Indicators

- Defined within strategy IR (from strategy_engine)
- Generated when strategy IR is compiled
- Only used by that specific strategy (unless explicitly shared)
- Examples: Custom composite indicators, strategy-specific EMAs

## Workflow

### Build Time

```
Python Scripts (Separate Workspace)
    ↓
Generate indicator configs
    ↓
Export to config/indicators.json
    ↓
Git commit / deploy
```

### Runtime

```
System Startup
    ↓
Indicator Engine loads config/indicators.json
    ↓
Strategy Engine loads strategies
    ↓
For each strategy:
    - Extract strategy-defined indicators (if any)
    - Merge with system indicators
    - Validate dependencies
    ↓
Register all indicators with Indicator Engine
```

## Integration

### With Python Layer

- Python scripts generate JSON configs
- Rust loads and validates JSON
- No runtime Python dependency

### With Indicator Engine

- Indicator Engine loads JSON configs at startup
- All indicators (system + strategy) registered with indicator_engine
- Indicator Engine handles calculation and updates

### With Strategy Engine

- Strategies can reference system indicators (by ID)
- Strategies can define their own indicators (in IR)
- Strategy Engine coordinates indicator registration

## Implementation

This directory structure is a placeholder. Implementation could be:

**Option A**: Python-only workspace
- Pure Python scripts in separate workspace
- Generate JSON, Rust loads it
- No Rust code needed here

**Option B**: Rust crate with Python bindings
- Rust provides validation/loading utilities
- Python scripts call Rust functions
- More integration but more complexity

**Recommendation**: Start with Option A (Python-only), add Rust validation later if needed.

## Configuration Format

```json
{
  "indicators": [
    {
      "id": "sma_20_btcusdt",
      "name": "SMA",
      "pair": "BTCUSDT",
      "period": 20,
      "source": "close"
    },
    {
      "id": "golden_cross_btcusdt",
      "name": "Golden Cross",
      "pair": "BTCUSDT",
      "type": "composite",
      "expression": { ... },
      "dependencies": ["ema_50_btcusdt", "ema_200_btcusdt"]
    }
  ]
}
```

## Validation Rules

1. All indicator IDs must be unique
2. All dependencies (for composite indicators) must exist
3. Indicator configs must be valid (period > 0, valid source, etc.)
4. No circular dependencies in composite indicators
